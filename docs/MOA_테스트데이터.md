## B-01 · PRD 원문 예시

- **출처:** 팀 PRD v1.1 §6의 원문 예시
- **사용 상태:** 사용 가능
- **실행 방법:** 아래 코드 블록을 처음부터 끝까지 복사해서 주문 입력 화면에 넣는다.

```text
[김민수] 아이스 아메리카노 톨 2잔, 하나는 샷 추가요.
[이지연] 바닐라라떼 큰 거 얼음 적게요.
[박서연] 아아 톨 한 잔이요.
[김민수] 아까 샷 추가한 한 잔 취소할게요.
[이지연] 사이즈는 벤티로 할게요.
스타벅스 기준으로 정리해줘
```

**예상 결과**

아이스 아메리카노 톨 2잔(김민수·박서연), 아이스 바닐라라떼 벤티 얼음 적게 1잔(이지연), 총 3잔. 예상 금액 16,200원(아이스 아메리카노 톨 4,700 × 2 + 아이스 바닐라 라떼 벤티 6,800).

**검증 메모:** 매장 기준은 요청 줄 "스타벅스 기준으로 정리해줘"로 정해진다(`brand_source=request`). 이벤트는 ADD · ADD · ADD · CANCEL · UPDATE. 샷 추가한 한 잔이 정확히 취소되고, 이지연의 "큰 거"는 확인 필요였다가 "벤티로" 메시지로 확정되는지 확인한다. 시드 별칭 "바닐라라떼"는 따뜻한 바닐라 라떼(`sb_013`)를 가리키므로, "얼음 적게"로 **아이스** 바닐라 라떼가 잡히는지도 확인한다.

**남길 증빙:** 전체 입력 화면, 매장 판정/모달(해당 시), 주문서 수량·변경·취소, 고정 메뉴 버전과 금액 비교, 최종 결과 화면

## B-02 · PRD 규칙 기반 보완안

- **출처:** 기존 테스트 실행기 data/baselines.json의 PRD 규칙 기반 보완안(팀 확정 필요)
- **사용 상태:** 사용 가능
- **실행 방법:** 아래 코드 블록을 처음부터 끝까지 복사해서 주문 입력 화면에 넣는다.

```text
[김민수] 아이스 아메리카노 레귤러 한 잔이요.
[이지연] 아이스 아메리카노 레귤러 두 잔이요.
```

**예상 결과**

**검증 메모:** 마지막 줄이 `[이지연]`으로 시작하므로 요청 줄이 아니다. 매장 이름이 없어 일반 카페로 정리되고 "매장 이름이 없어 일반 카페 메뉴로 정리했어요" 안내가 표시되는지(`brand_source=default`), 금액이 예상 금액으로 표시되는지, 동일한 사양의 총 3잔으로 묶이는지 확인한다.

**남길 증빙:** 전체 입력 화면, 매장 판정/모달(해당 시), 주문서 수량·변경·취소, 고정 메뉴 버전과 금액 비교, 최종 결과 화면

## 부록 A 출처·판정 유의사항

- **B-01:** 팀 PRD v1.1 §6에 있는 대화 원문 5줄과 끝의 매장 요청 1줄을 결합해 복사 입력으로 제공한다.
- **B-02~B-05:** 기존 테스트 프로그램에 들어 있던 보완안이며 PRD에서 다섯 건 전체를 공식 확정한 것은 아니다.
- **B-03:** 일반 카페 메뉴에 아이스 아메리카노(`gn_001`)가 등록되어 있어 조건부 판정을 해제했다. 메뉴 버전이 바뀌면 등록 여부를 다시 확인한다.
- **B-04:** 매장 충돌 시 분석 전에 모달에서 스타벅스를 선택해야 기대 결과와 비교 가능하다.
- **모든 케이스:** PRD의 SC-1은 5건 모두 수량·금액이 기준 데이터와 일치하는지를 요구한다. 예상 금액은 `mv_20261029` 기준이므로, 실행 시점 메뉴 버전이 다르면 금액을 다시 계산하기 전까지 `미검증`으로 남긴다.
- **개선 후 재시험:** 각 케이스의 테스트 ID와 입력 원문을 유지하고, 실행 버전/모델/메뉴 버전/시각과 실제 결과·캡처를 나란히 보관한다.
